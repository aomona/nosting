# アカウントのリレー設定

ログイン中は本人の署名済み NIP-65（kind 10002）だけをリレー設定として使います。設定画面には受信先・投稿先の単一の一覧を表示し、追加・削除・明示保存で編集します。ブラウザ用の接続編集や上書き解除は表示しません。ログインだけでは署名・公開しません。

[NIP-65](https://github.com/nostr-protocol/nips/blob/master/65.md) の `read` はメンション受信先、`write` は本人の投稿先、マーカー省略は両方です。一般的な接続権限とは別です。内部では受信先・投稿先の両方を読む接続にし、通知は受信先から取得し、投稿送信は `write` のみにします。

初期取得はフィード接続の完了を待たず、短時間の専用接続で行います。既定の探索先と発見した公開一覧を調べ、再接続時も確認します。未取得・取得失敗・未設定・明示的な空一覧を区別し、失敗を空一覧として公開しません。未設定・空一覧では内部の読み取り用 bootstrap を使いますが、投稿先を補わず、設定画面にも bootstrap を表示しません。検証済みの既知一覧は取得失敗や古い応答で消さず、セッション内で最大8アカウント分を保持します。

旧 `petal-relays-v1` は未ログイン時の接続設定として読み書きし、ログアウト時に戻します。ログイン中はゲスト設定も旧アカウント別 local override も適用・保存しません。旧アカウント別のデータは読み込まず、そのまま残します。一括削除や他アカウントへの流用はしません。

ログイン中に「この人のリレー」で「投稿を読む」を選ぶと、相手の投稿先へ読み取り専用の一時接続を追加します。プロフィールを離れる・別のプロフィールを開く・アカウントを切り替えると解除し、本人の公開一覧やゲスト設定には保存しません。

公開一覧は「署名して公開保存」でのみ更新します。

- 編集前と署名前後に取得し直し、既知のイベントより古い結果・取得失敗・他端末との競合を検出すると保存を止めます。取得できなかった一覧を空として扱いません。
- 空一覧の公開にはチェックが必要です。未対応の URL、拡張 `r` タグ、16件を超える一覧は欠落を避けるため編集できません。その他のタグと content は保持します。
- NIP-07 の返した公開鍵・kind・時刻・タグ・content・署名を検証します。同秒または未来の既存イベントに対して、未来の時刻を作って上書きしません。
- 旧一覧・新一覧・探索先へ送信し、対象ごとの `OK` を待ちます。一部成功と受信未確認を分けて表示します。設定画面を閉じる・ログアウト・アカウント切替で未完了の取得・保存を中止します。送信済みイベントは取り消せません。

## 制約

探索は既知のリレーの範囲です。ネットワーク全体の最新性や、最終確認から送信までの他クライアントとの競合を完全には保証できません。認証・有料リレーの自動認証は未対応で、取得できないリレーがある場合は安全な公開編集を止めます。接続先は既存の公開ホスト `wss://` 制約に従います。NIP-65 を用いた全投稿の宛先ユーザー別ルーティングや、全投稿先への kind 10002 の随伴配信はこの変更には含みません。

## 検証

`tests/account-relays.test.mjs` は一時鍵とモック WebSocket で、ゲスト保存の分離、旧上書きの不使用、read/write の変換、一時接続の投稿禁止、最新イベントと同時刻の選択、初期未接続、失敗・空一覧・未設定、再接続、古い応答の破棄、署名改変、競合、取消、リレー別 ACK を確認します。実アカウントや公開リレーへのテスト送信は行いません。
