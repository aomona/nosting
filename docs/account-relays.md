# アカウントのリレー設定

ログイン時に本人の署名済み kind 10002 を探索します。初期取得はフィード接続の完了を待たず、短時間の専用接続で行います。既定の探索先、アカウント別の接続先、発見した公開一覧を調べ、再接続時も確認します。ログインだけでは署名・公開しません。

[NIP-65](https://github.com/nostr-protocol/nips/blob/master/65.md) の `read` はメンション受信先、`write` は本人の投稿先、マーカー省略は両方です。一般的な接続権限とは別です。自動設定では受信先・投稿先の両方を読む接続にし、投稿送信は `write` のみにします。公開一覧が空なら、既定リレーでの読み取りだけを残します。未設定・未取得の場合は既定接続を使います。

「このブラウザの接続」の保存はアカウント別のローカル上書きです。公開一覧を変更しません。「公開一覧に合わせる」で上書きを解除します。旧 `petal-relays-v1` はゲスト用のまま保持し、ログインしたアカウントに流用しません。ログアウト時はゲストの設定に戻ります。

公開一覧は「署名して公開保存」でのみ更新します。

- 編集前と署名前後に取得し直し、既知のイベントより古い結果・取得失敗・他端末との競合を検出すると保存を止めます。取得できなかった一覧を空として扱いません。
- 空一覧の公開にはチェックが必要です。未対応の URL、拡張 `r` タグ、16件を超える一覧は欠落を避けるため編集できません。その他のタグと content は保持します。
- NIP-07 の返した公開鍵・kind・時刻・タグ・content・署名を検証します。同秒または未来の既存イベントに対して、未来の時刻を作って上書きしません。
- 旧一覧・新一覧・探索先へ送信し、対象ごとの `OK` を待ちます。一部成功と受信未確認を分けて表示します。設定画面を閉じる・ログアウト・アカウント切替で未完了の取得・保存を中止します。送信済みイベントは取り消せません。

## 制約

探索は既知のリレーの範囲です。ネットワーク全体の最新性や、最終確認から送信までの他クライアントとの競合を完全には保証できません。認証・有料リレーの自動認証は未対応で、取得できないリレーがある場合は安全な公開編集を止めます。接続先は既存の公開ホスト `wss://` 制約に従います。NIP-65 を用いた全投稿の宛先ユーザー別ルーティングや、全投稿先への kind 10002 の随伴配信はこの変更には含みません。

## 検証

`tests/account-relays.test.mjs` は一時鍵とモック WebSocket で、アカウント分離、read/write の変換、最新イベントと同時刻の選択、初期未接続、失敗・空一覧・未設定、再接続、古い応答の破棄、署名改変、競合、取消、リレー別 ACK を確認します。実アカウントや公開リレーへのテスト送信は行いません。
