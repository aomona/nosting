# フォロー中タイムライン

Issue #17。`lib/following-feed.ts` がフォロー中専用の購読・投稿集合・リレー別履歴カーソルを所有します。`components/following-feed.tsx` がアカウント、フォロー集合、読み取りリレー、タブの寿命と結び付け、ホームは既存の NoteList / M3E を再利用します。全体の最新45件や全体の履歴カーソルは使いません。

- [NIP-65](https://github.com/nostr-protocol/nips/blob/master/65.md): kind 10002 を設定済み読み取りリレーから探索し、署名検証後、最新の置換イベントを採用。同秒なら ID の辞書順最小を採用します。`r` の `write` またはマーカーなしを著者の投稿取得先として扱い、`read` のみは追加しません。一時接続は読み取りだけで、ユーザーの設定や公開一覧を書き換えません。
- 探索は最大3接続・3クエリ並列、200著者ずつ。探索接続を閉じてから投稿用最大6接続へ移行します。設定済みの先頭リレーをフォールバックとして保持し、残りはフォロー著者を多くカバーする outbox を優先。既存アプリの接続とは別の上限です。
- 著者は最大20,000、各著者のリレーは既存パーサーの最大16件。上限で未選択の outbox がある場合や探索が不完全な場合は短い状態文と再読み込み操作を表示します。新規の作者購読は空の authors を送信しません。
- [NIP-01](https://github.com/nostr-protocol/nips/blob/master/01.md): フィルター・フレーム・署名を受信時に検証。履歴はリレーごとに `until` を保持し、同秒を含む境界を重複して取得し ID で排除します。既存のカーソル実装を再利用し、50件から最大1,600件へ拡張しても境界を確認できなければ位置を進めず再試行します。
- ライブと履歴を分離。ライブは開始時刻以降、履歴は開始時刻以下を取得し、新着で過去カーソルを動かしません。取得済み投稿は約50msでまとめて描画し、遅いリレーを待たず表示。8秒の期限・CLOSED・切断でも成功済み投稿を保持し、正常なリレーの履歴を自動で読み進めながら失敗したリレーだけ再試行できます。正常なリレーが終端に達すると自動取得を止め、再試行後に残りがあれば再開します。
- [NIP-18](https://github.com/nostr-protocol/nips/blob/master/18.md): 既存の TimelineReposts / QuoteResolver を再利用。署名済みの kind 6 自身の時刻・ID・著者で並べ、検証済み kind 1 を描画します。本文なしリポストは選択済み接続で元投稿を照会し、リレー hint では接続先を増やしません。元投稿が取得できないリポストは描画しません。
- フォロー変更、アカウント切替、ホームからの離脱、タブ切替、アンマウントで購読・ソケット・タイマー・引用待ちを破棄。表示キーが変わった時点で前の結果を非表示にし、後着結果を無視します。再入場時は最新から取得します。
- 1,200投稿の保持上限では自動取得を止め、明示的に最新から読み直せます。ミュート、軽量表示、プロフィール取得、既存のノート操作は共通の描画経路を使用します。

## 検証

```sh
node tests/following-feed.test.mjs
npm test
npm run typecheck
npm run build
npm run lint
node tests/browser/following-server.mjs
# 別ターミナル
python tests/browser/following-feed.py
```

ブラウザーハーネスは実 App を使い、一時鍵で署名した架空の投稿・プロフィール・フォロー一覧だけを供給します。WebSocket はモック、HTTP はローカルサーバー以外を遮断、署名・公開処理は禁止。1280px / 390px で全体にはない古い投稿とリポスト、履歴追加、部分失敗と再試行、タブ・フォロー変更・アカウント切替、離脱後の接続破棄を確認します。画像は `/tmp/nosting-following-{1280,390}.png` と `-partial.png` に保存し、Git に追加しません。

## 制限

探索したリレーが知らない kind 10002、上限で選外になった outbox、リレーの保持期間・非準拠の limit、開始時刻以前の遅着イベントは完全性を保証できません。タイムアウトしたライブ購読は自動再接続せず、再試行で再開します。本文なしリポストの元投稿が選択済みリレーにない場合も表示対象外です。全リレーへの無制限な探索・接続、他 Issue の取得経路、引用投稿作成、画像表示は変更しません。
