# 通知の履歴取得

通知画面は各読み取りリレーの `kinds: [1, 6, 7]` / `#p` を50件ずつ取得する。表示末尾の IntersectionObserver と手動ボタンが同じコントローラーを使い、同時取得は1バッチに制限する。

- 履歴カーソルはリレー別。署名・フィルターを検証した生イベントで進めるため、ミュート、自己通知、対象投稿を確認できないリアクションによって取得位置がずれない。失敗したページは位置を保持し、成功したリレーを巻き戻さず再試行する。
- `until` は同秒を重ねる。境界で進まなければ50→100→200→400→800件に拡張する。拡張後も境界の完全性を確認できない応答や上限到達はエラーとし、その秒を飛ばさない。
- 対象投稿は全リレーの通知ページが揃ってから200 IDずつ問い合わせる。失敗リレーだけの再試行でも、他の読み取りリレーを対象投稿の照会に使う。対象投稿の署名、kind、投稿者検証と既存のミュート・センシティブ表示は維持する。
- 新着は独立した `since` / `until` の区間を使う。全件取得までその区間を保持し、30秒ごとの更新で続きから取得する。履歴読み込み中の更新は直後に実行する。新着区間を進めても履歴カーソルと表示済み通知は保持する。
- ID重複を除去して時刻降順・ID順に統合する。更新前に表示中の行の位置を記録し、Reactのレイアウト効果で復元する。既存の行とフォーカスを維持する。
- 最大1,200通知を保持し、上限では取得を停止して「最新から読み直す」を表示する。リレー数16、要求件数800、フレーム長65,536文字、バッチの保持文字数8 Mi文字、メッセージ数と12秒のタイムアウトにも上限を設ける。完了後の一時バッファは解放する。
- 非表示タブはタイマーとソケットを閉じる。アカウント・リレー設定変更、画面離脱時はコントローラーを破棄し、以前の応答を無視する。

Nostrには安定したページトークンがない。リレーの保持期間、非準拠の取得上限、取得後の削除、完了した区間より古いタイムスタンプの遅着イベントまでの完全性は保証できない。同秒境界で曖昧な場合は終端と誤認せず、取得済みの内容と再試行を表示する。

## 検証

`npm test` には、実際に署名したイベントを使った複数リレーの通信・コントローラー統合テストを含む。65件が同秒に集中する145通知の履歴を欠落・重複なく取得すること、部分失敗と独立した再試行、新着の未完了区間、対象投稿の別リレー照会、署名不正・範囲外イベント、上限・タイムアウト、タイマーの単一所有と破棄を確認する。

ブラウザ検証はローカルの専用フィクスチャで行う。Python Playwright と Chromium が利用できる環境で、リポジトリ直下から別々の端末で実行する。`CHROMIUM_PATH` でブラウザの場所を指定できる。

```sh
node tests/browser/server.mjs
python tests/browser/notification-feed.py
```

1280×900 / 390×844で、49→98件への追加取得、重複のない180件への到達、ミュート、エラー・再試行・終端、新着追加時の行位置（差分0px）とフォーカス維持、アカウント切替中の古い応答と離脱時のソケット解放、横はみ出し・コンソールエラーなしを検証する。スクリーンショットは `/tmp/nosting-notifications-*.png` に保存する。

このフィクスチャはWebSocketをローカルモックに置き換え、REQ / CLOSE以外を拒否する。ブラウザから外部URLへの通信も遮断する。実アカウント、外部投稿、リレーへの公開書き込みは使用しない。
