# 返信・メンションの NIP-65 配信

Issue #18。kind 1 の既存 `p` タグ（返信先・本文の公開鍵メンション）を使います。引用投稿の作成、リアクション、DM、受信設定の編集には変更を加えません。

- 投稿時に bootstrap と現在の read リレーへ kind 10002 を問い合わせます。ID・署名・所有者・時刻・イベントサイズを検証し、問い合わせ先で見つかった最新を採用します。同時刻は NIP-01 に従い ID の辞書順で選びます。
- 自分の write 設定と相手の read（marker なしを含む）を URL 正規化して重複排除します。相手の write のみのリレー、`p` タグの relay hint、無関係なイベントは接続先に使いません。
- 一時ソケットから同じ署名済み投稿と本人の検証済み kind 10002 を送ります。取得済み本人一覧を再利用し、追加署名・設定の自動公開は行いません。各宛先の両イベントの OK を待ち、拒否・接続失敗・期限切れを未確認として数えます。保存済み設定や常駐接続一覧は変更しません。
- 投稿の OK が一つでもあれば投稿を表示し、下書きを消去します。0 件なら下書きを保持し、再投稿前の確認を促します。宛先一覧未発見、探索の一部失敗、省略、本人一覧未発見／共有の一部失敗は短い通知で区別します。明示的な空の受信一覧は未発見とは区別します。
- 署名内容をコピーして完全一致・署名を確認し、署名拒否、返信欄のアンマウント、アカウント変更（同じ鍵への復帰を含む）、アプリのアンマウントで未完了処理を中止します。既にリレーへ送ったイベントは取り消せません。自動再投稿はしません。

## 上限・制限

1 投稿あたり受信者16人、探索8リレー、相手1人あたりread 4件、追加16リレー、自分のwriteを含む最大32宛先。配信は同時4接続、1接続最大8秒、配信全体24秒。探索は最大8秒・1ソケット256フレームです。上限で省略した場合は完全成功として扱いません。

相手由来のURLは明示的な `wss://`・443・公開DNS名に限定します。IPリテラル（IPv4省略／数値表現・IPv6を含む）、localhost・内部向けsuffix、末尾ドット、認証情報・query・fragment・非標準ポートを拒否します。**ブラウザのWebSocket APIから接続先IPを検査・固定できないため、公開DNS名が私設IPへ解決される場合やDNS rebindingを、このURL検証だけで完全には防げません。** ネットワーク境界での完全な私設IP遮断は未対応です。DNS検証プロキシやサーバー転送はこのPRに追加していません。

最新性は問い合わせたリレーの範囲です。見つからない相手には自分のwriteのみへ投稿します。相手の未対応／上限超過URL、認証必須リレー、相手の受信一覧が探索先に存在しない場合の再帰探索は未対応です。本人の write は送信開始時のアカウント設定を使います。本人一覧の取得後・署名中に別クライアントが一覧を更新する競合は完全には防げません。

## 検証

`tests/recipient-relays.test.mjs` は一時テスト鍵とモックWebSocketのみを使います。共有リレーなし、両イベントのACK、最新／同時刻／改ざん／別所有者／未来イベント、空／未発見／部分障害、URL拒否、上限・同時接続、アカウント切替・中止、署名内容改変、実Appの投稿コールバックを検証します。公開リレーへのテスト送信は行いません。
